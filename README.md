Локальная программа для поиска интересных отрезков мотоциклетных поездок в MP4 и экспорта вертикальных шортсов. Компактное окно содержит округлые карточки выбора файлов, списка кандидатов и управления обработкой. Кнопки закруглены, поддерживают наведение, фокус с клавиатуры, Enter и пробел. Индикатор выполнения имеет закруглённые края и бирюзово-розовую градиентную заливку. Параметры анализа, границ и экспорта открываются в отдельных небольших окнах с округлыми карточками. В шапке используется плавный тёмный градиент с бирюзовым и розовым свечением. Исходный MP4 не меняется и не загружается в облако.

В v22 заголовки таблицы сортируют список фрагментов по имени видео, баллу, началу, концу, длине, причине, выбору и проверке. Редактор **ГРАНИЦЫ** показывает два кадра исходного видео и позволяет выбирать шаг сдвига **1 с / 5 с**. Базовые зависимости прежние; для новых функций v23 установите дополнения по инструкции ниже. Для обновления v20/v21/v22 закройте программу и скопируйте всё содержимое папки из архива в прежнюю папку программы с заменой файлов. Существующие `.venv`, `learning_data`, проекты и папка вывода сохраняются. Если запускаете программу в новой папке, перенесите в неё прежнюю папку `learning_data`, чтобы использовать свою модель и разметку.

## Исправления v23.1 — загрузка, анализ и очистка

Полный цикл проверен на настоящем коротком MP4: загрузка через Google SDK → декодирование FFmpeg → сохранение числового анализа и признаков в SQLite → запись проекта → удаление временной загрузки → восстановление проекта без повторного скачивания. Повторная загрузка того же оригинала тоже проверена. В этих тестах ответы Google и тяжёлый визуальный кодировщик подменены контролируемыми данными; чужие аккаунты не используются.

- Повторное добавление изменённого облачного файла создаёт отдельную запись загрузки. Старый путь и старые события остаются привязаны к прежней версии; просмотр прежних событий не скачивает новую запись вместо старой.
- Изменённый или вручную заменённый временный MP4 не перезаписывается скачиванием. Его нужно переместить из папки загрузок, если вы хотите скачать оригинал снова.
- СТОП проверяется после сохранения проекта и непосредственно перед удалением. Остановка в этот момент оставляет MP4. При продолжении готового проекта очистка выполняется без повторного анализа и загрузки, если она включена.
- Перед удалением проверяются все признаки текущих кандидатов, их версия и целостность. Недостаточно одного сохранённого флага «готово»: отсутствие или повреждение вектора блокирует очистку.
- Галочка автоматического удаления сохраняется после перезапуска программы. Кнопка ОЧИСТИТЬ ЗАГРУЗКИ остаётся отдельной явной командой.
- При ошибке признаков или записи проекта исходник остаётся. При прерванном скачивании удаляется только незавершённый `.part`, а не пригодный исходник.

Дополнительно в реальном окне Tk 9.0 проверены кнопки очереди Drive, сохранение галочки очистки, анализ с фоновой обработкой, удаление временного MP4, открытие памяти событий и возобновление проекта без повторного скачивания. Основные кнопки помещаются при размере 900×630; ошибок обратных вызовов не обнаружено.

Новая краткая инструкция: `Moto_Shorts_v23_1_INSTRUCTIONS.txt`. Обновляйте прежнюю папку программы с заменой файлов; установщик дополнений по-прежнему называется `Установить_дополнения_v23.bat`.

## Что добавлено в v23

- **Память событий без видео.** В `learning_data/moto_events/events.sqlite3` сохраняются таймкоды, оценки, исходная поездка, числовые сигналы, траектории объектов, звуковые события, текст/время слов и замороженные визуальные признаки X-CLIP. Кадры, аудиофайлы и MP4 в памяти событий не сохраняются. Кнопка **АНАЛИЗ** показывает сведения выбранной строки; **ПРОЕКТ → ПАМЯТЬ СОБЫТИЙ** показывает последние 1000 кандидатов, включая не прошедшие порог.
- **Повторное обучение без оригиналов.** После получения признаков «Принять / Исключить» можно использовать даже при удалённом MP4. Обучение использует сохранённые признаки и разделение по исходным поездкам. Старую разметку нужно обработать/обучить один раз с доступными оригиналами. Если признаки не получены или несовместимы по версии, программа явно просит исходник и сохраняет прежнюю модель.
- **Переоценка архива.** В памяти событий кнопка **ПЕРЕОЦЕНИТЬ** применяет текущий обученный классификатор к сохранённым признакам; MP4 и большие веса X-CLIP не нужны. Меняется оценка в архиве; уже открытый проект и готовые шортсы не переписываются. Числовые признаки не восстанавливают видео и не позволяют обучить другой визуальный кодировщик без исходных кадров.
- **Трекинг BoT-SORT.** Объекты получают устойчивые ID; движение камеры компенсирует трекер. Кадры для объектов берутся примерно с частотой 6/с внутри кандидата. По траекториям выделяются приближение, пересечение кадра и встреча с человеком/мотоциклистом. Это признаки событий по изображению, не измерение физического расстояния.
- **Локальная речь.** Дополнительная галочка **Речь и границы реплик** запускает faster-whisper Base на CPU в int8, с VAD и временем слов. Речь ищется по всей записи, поэтому разговор может стать кандидатом без всплеска движения. После анализа остаётся текст, а не аудиозапись. Качество распознавания при ветре/шуме нужно проверить на ваших видео; наличие речи само по себе не доказывает интересность.
- **Границы событий.** В автоматическом режиме учитываются начало/завершение движения объекта, контекст и пересекающиеся реплики. Ручные границы автоматически не передвигаются. Фиксированная длина сохраняется. Стыки нескольких исходных файлов автоматически не склеиваются.
- **Разнообразие.** Фильтр похожих отрезков дополнительно использует визуальные признаки и мягко предпочитает разные типы событий. Его можно выключить прежней галочкой. Порог интересности продолжает действовать.
- **Google Drive.** Выбор MP4/папки/подпапок, очередь с загрузкой по одному оригиналу, проверка размера/контрольной суммы и доступ только на чтение. Удаляются только загрузки, созданные программой, после успешного сохранения анализа и всех признаков кандидатов. После ошибки/остановки незавершённый исходник сохраняется. Просмотр, правка границ и экспорт при необходимости повторно скачивают тот же файл по ID; изменившийся оригинал требует нового добавления в очередь. Файлы в облаке не удаляются.

### Обновление и установка дополнений

1. Закройте программу и скопируйте **всё содержимое папки из ZIP** в прежнюю папку с заменой. Сохраните существующие `.venv`, `learning_data`, проекты и папку вывода. Если переносите программу в другую папку, перенесите всю `learning_data`, включая `moto_events` и `moto_learning`.
2. Запустите **Установить_дополнения_v23.bat**. Для новой папки сначала один раз запустите **Запустить.bat**, закройте окно программы и затем установите дополнения. Отдельно доступны **Установить_речь.bat**, **Установить_Google_Drive.bat**, прежние установщики ИИ/обучения.
3. Откройте **Запустить.bat**, выберите видео и включите нужные галочки объектов, звуков и речи. Визуальные признаки для памяти событий сохраняются при анализе автоматически. Первый запуск скачивает веса моделей; работа выполняется локально. Техническая телеметрия ONNX Runtime, Hugging Face и Ultralytics отключена до загрузки моделей. Сохранение признаков увеличивает время первого анализа.
4. Перед удалением локальных оригиналов откройте **ПРОЕКТ → ПАМЯТЬ СОБЫТИЙ** и проверьте **ПРИЗНАКИ: Есть**. Если зависимости обучения не установлены или модель не загрузилась, сохраняются только сведения; временные загрузки Drive не удаляются автоматически. Выбранные вручную локальные MP4 программа не удаляет.
5. Отметьте хорошие/плохие кандидаты и нажмите **ОБУЧИТЬ И ПРОВЕРИТЬ**. Новая модель выключена до вашего включения. Метку, описание и группу поездки можно менять без MP4; новые границы требуют оригинала.

### Подключение Google Drive

Google OAuth-клиент для этой настольной программы создаётся в вашем проекте Google Cloud. Ключей автора в архиве нет. Настройка:

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте/выберите проект. Включите **Google Drive API**.
2. Откройте **Google Auth platform → Branding**, задайте имя приложения и свою почту. Для личного аккаунта в **Audience** выберите **External**, оставьте тестовый режим и добавьте свой Google-аккаунт в **Test users**. Для аккаунта организации допустим Internal, если он доступен.
3. В **Data Access** добавьте `https://www.googleapis.com/auth/drive.readonly`.
4. В **Clients → Create client** выберите **Desktop app**, создайте клиента и скачайте JSON. Не отправляйте OAuth JSON и `token.json` другим людям.
5. В программе откройте **ПРОЕКТ → GOOGLE DRIVE → ПОДКЛЮЧИТЬ GOOGLE**, выберите этот JSON и завершите вход в браузере. Кнопка **СТОП** отменяет ожидающий вход. Токен сохраняется локально в `learning_data/moto_drive/token.json`.
6. Вставьте ссылку на папку Drive или оставьте поле пустым для всех доступных MP4. Нажмите **ПОКАЗАТЬ MP4**, выделите записи (Ctrl/Shift или ВЫБРАТЬ ВСЕ) и нажмите **В ОЧЕРЕДЬ**. Затем запустите **НАЙТИ МОМЕНТЫ**.
7. Галочка удаления временных загрузок включена по умолчанию. Успешно обработанный оригинал удаляется с компьютера, анализ остаётся. Двойной щелчок загрузит оригинал снова для просмотра. Для освобождения просмотренных загрузок используйте **ОЧИСТИТЬ ЗАГРУЗКИ**; исходники без сохранённых признаков останутся.

Если вход в тестовое приложение истёк, подключите Google повторно. Официальные инструкции: [Python quickstart](https://developers.google.com/workspace/drive/api/quickstart/python), [OAuth для настольных приложений](https://developers.google.com/identity/protocols/oauth2/native-app), [скачивание файлов](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

### Следующий шаг по обучению (пункт 5)

Предлагаемый процесс: 10–20 неоднозначных кандидатов за короткую сессию → ваши «интересно / обычно», с отдельными причинами качества, границ и повторов → ручное обучение → сравнение на заранее отложенных полных поездках. Добавить отдельный ввод пропущенного события по таймкоду, пока оригинал доступен. Показатели: доля принятых кандидатов, пропуски на контрольных поездках и время ваших ручных правок. Сравнивать версии модели и сохранять возможность возврата. Это план следующего шага; автоматической разметки и обучения после каждого клика в v23 нет.

## Запуск на Windows

1. Установите Python 3.10–3.12 с [python.org](https://www.python.org/downloads/windows/). При установке отметьте **Add python.exe to PATH**.
2. Распакуйте архив в **новую папку** и дважды нажмите **Запустить.bat**. При первом запуске будут установлены NumPy и FFmpeg.
3. Нажмите **ФАЙЛЫ** для нескольких MP4 или **ПАПКА MP4** для всех MP4 в одной папке без вложенных папок.
4. Нажмите **НАЙТИ МОМЕНТЫ**. По умолчанию длина выбирается автоматически; задайте число фрагментов на одно видео и нужные виды дополнительного анализа. Сняв галочку **«Авто»**, можно задать фиксированную длину 10–120 секунд. Пункт **«Ускорять анализ через одноимённые .LRF»** включён по умолчанию.
5. В списке дважды щёлкните по строке, чтобы открыть исходное видео **с начала найденного отрезка**. Кнопки **ПРИНЯТЬ** и **ИСКЛЮЧИТЬ** управляют выбором; пробел переключает выбранную строку. После экспорта кнопка **ГОТОВЫЙ РОЛИК** откроет её результат.
6. Нажмите **СОЗДАТЬ ШОРТСЫ**. Во всплывающем окне выберите папку вывода, вертикальное кадрирование и цветокоррекцию.

## Сортировка списка — v22

Нажмите заголовок любого столбца таблицы. **ВИДЕО** сортирует по имени без учёта регистра, учитывая числа в названиях: DJI_2 идёт перед DJI_10. **БАЛЛ** первым нажатием показывает самые высокие оценки, **НАЧАЛО**, **КОНЕЦ** и **ДЛИНА** — самые маленькие значения. Значения сравниваются по исходным числам, включая дробные секунды и точность баллов. **ПРИЧИНА** сортирует по тексту; **ВЫБРАН** и **ПРОВ.** первым нажатием показывают выбранные и проверенные фрагменты первыми. Повторное нажатие меняет направление, обозначенное **▲ / ▼** в активном заголовке. Баллы, которые ещё не рассчитаны, остаются внизу в обоих направлениях.

Порядок отображения сохраняется при обновлении оценок и после ручных правок до закрытия программы. Выделение, просмотр исходника, границы, обучение и готовые файлы остаются привязаны к своему фрагменту. После пересортировки строки получают соответствующую чередующуюся подсветку; выбранные для экспорта фрагменты по-прежнему подсвечиваются отдельно.

## Обучение на городских видео — v20

1. Запустите **Запустить.bat** один раз, закройте программу и запустите **Установить_обучение.bat**. Затем снова откройте программу. Для обучения достаточно этого установщика; объекты и звуковые модели ставятся отдельно через **Установить_ИИ.bat**.
2. Откройте **ПРОЕКТ → ОБУЧЕНИЕ ОТБОРА**. Нажмите **ГОРОДСКИЕ ПРИМЕРЫ**: программа импортирует 18 меток, подключит готовую пилотную модель и загрузит 13 публичных коротких MP4. В архиве программы есть разметка и маленький классификатор, сами видео и большие веса X-CLIP скачиваются отдельно. Первый анализ сюжета может скачать около 600 МБ весов; ваши MP4 остаются на компьютере.
3. Нажмите **РЕЗУЛЬТАТ ПРОВЕРКИ**, чтобы посмотреть результат уже выполненного пилота. Двойной щелчок по метке открывает её отрезок в установленном VLC/mpv/ffplay. Системный плеер без поддержки таймкода откроет весь MP4 и покажет нужное время.
4. Для своих поездок нажимайте **СВОЯ МЕТКА**: выберите MP4, начало, конец и тип «Событие» / «Обычный отрезок». В поле группы укажите одинаковое имя для всех частей одной поездки, исходника и его копий. Кнопка **ИЗМЕНИТЬ МЕТКУ** позволяет исправить импортированную разметку. **ПРИВЯЗАТЬ MP4** подключает выбранный источник, а **ПАПКА MP4** сопоставляет файлы по именам и проверяет контрольные суммы публичных примеров.
5. Нажмите **ОБУЧИТЬ И ПРОВЕРИТЬ**. Нужны минимум 5 событий, 5 обычных отрезков и 3 независимые исходные записи. Обе категории должны встречаться в нескольких записях. Сначала получаются признаки коротких окон X-CLIP, затем обучается небольшой регуляризованный классификатор «событие / обычная езда». Сам X-CLIP остаётся неизменным. Проверка по очереди полностью исключает каждый исходник и его совпадающие копии из обучения.
6. После проверки включите **«Использовать обученную модель при следующем поиске»** и запустите новый поиск через **НАЙТИ МОМЕНТЫ**. Каждая новая обученная модель первоначально выключена. Продолжение старого проекта с другой моделью запускает пересчёт, чтобы не смешивать оценки разных моделей.

Обучение общее для программы: разметка, модель и настройка включения находятся в `learning_data/moto_learning` рядом с файлами программы. Модель доступна для поездок из разных папок и сохраняется после перезапуска. Признаки X-CLIP кэшируются в `learning_data/moto_cache/video_features`: повторное обучение и повторный анализ тех же окон не запускают нейросеть заново. Изменение MP4, таймкодов или версии признаков требует новых вычислений. Рядом хранится подробный `training_report.json` с группами, результатами и ограничениями проверки.

Если модель включена, программа дополнительно проверяет всю запись окнами до 6 секунд по 8 кадров. Это позволяет находить визуальные события без всплеска движения. После оценки кандидатов модель должна признать отрезок событием (балл сюжета от 0.5). Сильное распознанное звуковое событие (от 0.8) также допускает кандидата, даже если визуально кадр обычный. Затем применяются общий порог интересности, ограничение количества и фильтр повторов. Общий балл состоит из 45% прежней оценки и 55% обученного сюжета; персональные предпочтения, если уже накоплены, добавляются как раньше. Пересекающиеся кандидаты одного исходника выбираются по одному. Обученный классификатор заменяет общую оценку сюжета по текстовым подсказкам, чтобы не держать две копии X-CLIP. Объекты, звук и телеметрия остаются дополнительными сигналами. Осмысленный анализ требует больше времени, чем быстрый поиск по движению; выключенная модель позволяет пользоваться прежним режимом.

Явные **ПРИНЯТЬ** и **ИСКЛЮЧИТЬ** автоматически сохраняют таймкоды для следующего обучения. Они не переобучают большой классификатор после каждого щелчка: для учёта новых меток нажмите **ОБУЧИТЬ И ПРОВЕРИТЬ** снова. Отказы из-за границ, повторов и качества не учат визуальную модель считать сюжет неинтересным. Старое обучение предпочтениям в `moto_preferences.json` продолжает работать отдельно. Публичные метки не записываются в вашу историю предпочтений.

Можно импортировать прежний **Moto_Urban_Training_Tests.zip**, `urban_dataset.json` или новый JSON разметки через **ИМПОРТ МЕТОК**. Старый экспериментальный архив не содержит MP4: загрузите примеры соответствующей кнопкой либо подключите собственную папку с теми же файлами. Нормализованные MP4 из предыдущего эксперимента тоже поддерживаются: их сдвиг относительно опубликованного видео учитывается при совпадении контрольной суммы.

### Что показал пилот

Реальные признаки X-CLIP извлечены из 18 размеченных отрезков 13 публичных городских нарезок. В проверке с исключением источника визуальная модель нашла **6 из 8** событий и выбрала **2 из 10** обычных отрезков; быстрый исходный анализ на тех же MP4 — **7 из 8** событий и **7 из 10** обычных отрезков. Это разработческий пилот, а не итоговая независимая оценка качества. Правило допуска обученного сюжета уточнялось после первого прогона на этой же маленькой выборке; после обновления нужны новые записи для окончательной проверки. Порог модели 0.5 и параметры классификатора фиксированы; итоговая модель обучается на всех метках после проверки.

Эти метки созданы помощником и ещё не проверены вами. Они описывают видимое событие, а не популярность рилса. Источник части публикаций неизвестен; визуально изменённые копии программа не умеет гарантированно объединять автоматически. Короткие готовые нарезки не проверяют точный выбор начала и конца в длинной поездке. Для следующего этапа нужны ваши полные городские MP4 с обычной ездой, остановками, общением, встречами с другими мотоциклистами и примерами событий, которые вы действительно хотите видеть в рилсах. Звук и GPS этим пилотом не обучались.

### Обновление старой папки

Закройте программу. Скопируйте файлы из новой папки архива в прежнюю папку программы с заменой, включая новые `learning.py`, `video_features.py`, `training_ui.py`, `requirements-learning.txt`, `Установить_обучение.bat` и папку `training_examples`. Существующие `.venv`, `learning_data`, проекты, исходные MP4 и папки с готовыми шортсами сохраните. Запустите установщик обучения после копирования. Можно распаковать в отдельную новую папку; для переноса своей обученной модели скопируйте в неё `learning_data` целиком.

## Проект, кэш и продолжение очереди

Кнопка **ПРОЕКТ** открывает сохранение, загрузку проекта, продолжение очереди и проверку оборудования. При анализе `moto_project.json` автоматически сохраняется в папке вывода после каждого полностью обработанного видео — даже если в нём не найдено хороших моментов. Сохраняются очередь файлов, параметры, таймкоды, оценки, ручные правки, принятые/исключённые строки и пути готовых шортсов. Кнопка **СОХРАНИТЬ КАК…** позволяет выбрать другой файл проекта.

После остановки или перезапуска нажмите **ПРОЕКТ → ОТКРЫТЬ ПРОЕКТ**, затем **ПРОДОЛЖИТЬ ОЧЕРЕДЬ**. Продолжение пропускает уже обработанные неизменённые исходники и сохраняет ваши правки. Новый запуск через **НАЙТИ МОМЕНТЫ** заново формирует выборку с текущими настройками и предпочтениями, используя кэш. Удалённый MP4 теперь выдаёт понятное сообщение с именем файла и предложением подключить диск. Изменённые или удалённые исходники не считаются обработанными; перемещённые MP4 нужно вернуть по прежним путям. Экспорт после открытия проекта запускается явно, а не автоматически. Проект содержит ссылки, не копии видео. Он не является резервной копией MP4.

В `moto_cache` рядом с проектом по умолчанию сохраняются сжатые массивы движения, звука, качества и малые визуальные признаки, а также успешные оценки дополнительного ИИ. Кэш учитывает размер, время изменения, путь, контрольную сумму начала/конца MP4 и используемого LRF. Изменение длины или количества кандидатов использует прежнее сканирование, новые границы/режимы ИИ требуют только соответствующей дополнительной оценки. Кэш можно удалить при закрытой программе: следующий анализ создаст его заново. Для сохранения проекта и обучения при обновлении программы используйте прежнюю папку вывода.

## Выборка и производительность

В окне анализа **Порог интересности** задаёт минимальную итоговую оценку (по умолчанию 0,22). **На одно видео** теперь означает максимум: программа может найти меньше фрагментов или ни одного. Оценка не является калиброванной вероятностью. Если отбор слишком строгий, снизьте порог; 0 позволяет рассматривать все кандидаты.

**Убирать похожие фрагменты** сравнивает компактные визуальные признаки, тип события и длину в текущей партии. Это эвристика для разнообразия, а не точное распознавание одинаковых сюжетов. Её можно отключить, чтобы сохранить похожие повороты или обгоны. Список по-прежнему требует вашего просмотра.

**Авто**, **Экономный** и **Максимальная скорость** автоматически выбирают число потоков CPU и размер пакетов ИИ по доступной памяти. Экономный профиль ограничивает нагрузку; быстрый допускает больше потоков/кадров в пакете. Частота проверки событий и разрешение ИИ при смене профиля не снижаются. Файлы обрабатываются последовательно: параллельная загрузка нескольких больших видео и моделей не используется.

Для ИИ проверяются поддержка CUDA в установленном PyTorch, свободная видеопамять и выполнение небольшой операции на GPU; на поддерживаемых Mac также проверяется MPS. Объекты обрабатываются пакетами, модели остаются загруженными между анализами одного режима. При нехватке видеопамяти пакет уменьшается; при повторном сбое модели переводятся на CPU. Наличие видеокарты не гарантирует её поддержку пакетами/драйверами: при недоступном GPU программа продолжает на CPU. Программа не устанавливает драйверы автоматически.

Перед экспортом программа проверяет доступные H.264 NVENC / QSV / AMF / VideoToolbox реальным коротким кодированием и выбирает рабочий ускоритель. Если экспорт с ним не проходит, текущий ролик повторно кодируется через CPU/libx264. H.264, размер и цветокоррекция сохраняются; параметры качества аппаратных и программных кодировщиков могут дать разные размер/битрейт. Ускоряется кодирование, но масштабирование, размытие и LUT всё ещё могут выполняться на CPU. **ПРОЕКТ → ПРОВЕРИТЬ ОБОРУДОВАНИЕ** показывает выбранные устройства и ограничения. Скорость зависит от исходного кодека, разрешения и компьютера; гарантированный коэффициент ускорения не задаётся.

### Остановка обработки

Кнопка **ОСТАНОВИТЬ** активна во время анализа, экспорта и подготовки временного отрезка для внешнего плеера. Она прерывает текущий FFmpeg и не запускает следующие файлы. Найденные фрагменты полностью обработанных исходников остаются в списке; готовые шортсы остаются на диске, недописанный временный MP4 удаляется. Существующий готовый ролик заменяется только после успешного экспорта. Если выполняется вызов ИИ-модели или загрузка её весов, остановка завершится после возврата из этого вызова. Дождитесь статуса **ОСТАНОВЛЕНО**. Продолжение через проект начинается с незавершённого файла; уже сохранённое сканирование этого файла берётся из кэша.

### Ручная правка начала и конца

Выберите строку и нажмите **ГРАНИЦЫ** или **F2**. В отдельном округлом окне расположены две карточки: **НАЧАЛО** и **КОНЕЦ**, каждая с кадром, таймкодом, кнопками сдвига и ползунком. Выберите **ШАГ СДВИГА: 1 с / 5 с**; кнопки обеих границ переключаются на выбранный шаг. Выбор шага запоминается до закрытия программы. Стрелки влево/вправо на ползунке сдвигают границу на выбранный шаг, Shift со стрелкой — на пять секунд. Можно также вводить точный таймкод `ЧЧ:ММ:СС.сс` / число секунд. Длительность пересчитывается сразу. **СОХРАНИТЬ И ОТКРЫТЬ** применяет границы и открывает обновлённый отрезок внешним плеером; **ОТМЕНА** оставляет прежние границы. При ручной правке допустима любая положительная длина в пределах исходной записи, включая более 90 секунд.

Слева показывается первый видеокадр на выбранном начале или сразу после него. Справа — последний кадр строго перед выбранным концом: кадр за границей нарезки не показывается. Под изображением указан фактический таймкод кадра, который может немного отличаться от введённого времени из-за частоты кадров. Кадры извлекаются из оригинального MP4 без LUT и цветокоррекции экспорта, с сохранением пропорций, включая вертикальное видео. Изображение имеет размер не более 360×202 пикселей; постоянно работающего плеера нет.

После изменения границы чтение начинается с задержкой 250 мс, чтобы не декодировать видео на каждое движение ползунка. Работает один фоновый декодер, очереди хранят только последние запросы обеих границ; устаревшее чтение отменяется. Повторные таймкоды берутся из небольшого кэша в памяти (до 24 изображений / 5 МБ). После закрытия окна чтение прекращается. Пока загружается новый кадр, старое изображение скрывается, чтобы не приписывать ему новый таймкод. Ошибка чтения показывается внутри карточки; править и сохранять корректные таймкоды можно и без изображения.

После изменения границ автоматически пересчитываются признаки нового отрезка, включая включённые виды ИИ. Пока проверка выполняется, можно остановить её; при незавершённой проверке этот пример не обучает предпочтения. Нажмите **ПРИНЯТЬ** после проверки, чтобы подтвердить хороший пример. Уже экспортированный файл остаётся на диске, но кнопка **ГОТОВЫЙ РОЛИК** требует нового экспорта, чтобы не открывать старый вариант. Правки автоматически сохраняются в проекте.

### Внешний просмотр

В режиме **Авто** программа ищет пики движения и звука, расширяет границы до трёх секунд затихания и добавляет контекст до и после события. Обычно длина составляет 10–90 секунд; короткая исходная запись сохраняется целиком. Это эвристика по сигналам, а не гарантия завершённого сюжета: перед экспортом проверяйте кандидатов. В v23 границы дополнительно уточняются по речи и динамике объектов, если соответствующий анализ включён. Колонка **ДЛИНА** показывает длительность каждого отрезка. Дополнительный ИИ затем оценивает и ранжирует эти кандидаты.

Для открытия исходного MP4 по таймкоду программа ищет **VLC**, затем **mpv**, затем **ffplay** (в PATH или в стандартной папке установки VLC на Windows). Плеер запускается на нужной секунде и останавливается в конце фрагмента. Если такого плеера нет, программа создаёт временную уменьшенную копию выбранного отрезка и открывает её системным видеоплеером. Первая подготовка может занять несколько секунд; встроенного проигрывателя и автоматической последовательной проверки больше нет. Временные отрезки удаляются при закрытии программы, если операционная система разрешит удалить открытые файлы.

## Быстрый анализ через DJI LRF

Файлы с расширением **.LRF** (возможно, именно их вы имели в виду под «LHR») — облегчённые копии DJI для воспроизведения. Положите исходный `.MP4` и одноимённый `.LRF` **в одну папку**, например `DJI_0001.MP4` и `DJI_0001.LRF`. Программа сверяет имя и длительность. При совпадении движение и кадры дополнительного ИИ-анализa читаются из LRF; звук и доступная телеметрия читаются из исходного MP4. Двойной щелчок открывает MP4 по таймкоду. Готовый шортс всегда кодируется из исходного MP4 в полном качестве.

Если LRF отсутствует, не читается либо существенно отличается по длительности, программа анализирует MP4 и показывает замечание о неподходящем LRF. Для проверки разницы снимите галочку LRF в окне анализа; в терминале используйте `--no-lrf`. Облегчённая копия может ускорить именно поиск моментов, особенно на 4K HEVC; экспорт из оригинала всё равно требует его декодирования. Небольшие объекты в LRF могут распознаваться хуже, чем в полном MP4. Не удаляйте MP4: без него программа не сможет создать шортсы высокого качества.

## Цветокоррекция Osmo Action 5 Pro

В окне экспорта есть режимы **Без коррекции**, **Ручная настройка** (яркость, контраст, насыщенность) и **D-Log M + LUT**. LUT DJI Osmo Action 5 Pro D-Log M → Rec.709 V1 уже входит в программу: выберите **D-Log M + LUT**, скачивать или выбирать `.cube` отдельно не требуется. Кнопка **ДРУГОЙ LUT** позволяет подключить свой файл; **ВСТРОЕННЫЙ DJI** возвращает встроенный вариант, в том числе если в старом проекте сохранился путь к внешнему LUT. При переносе программы сохраняйте папку `assets`. Применяйте этот LUT только к D-Log M; для Normal и HLG выберите соответствующий способ обработки. Настройки действуют на всю текущую партию; смешанные режимы съёмки экспортируйте отдельно. При экспорте создаётся H.264 MP4 720×1280, 8 бит, Rec.709; исходные записи не перезаписываются. Чтобы проверить цвет, откройте готовый ролик из списка.

По умолчанию полная ширина исходного кадра остаётся поверх размытого вертикального фона. «По центру» заполняет вертикальный кадр, но обрезает боковые области.

## Дополнительный анализ и обучение

Базовый поиск сравнивает движение и громкость с ближайшими участками той же поездки. Во всплывающем окне можно дополнительно включить объекты, звуковые события, короткий сюжет и телеметрию. Для трёх режимов с ИИ сначала запустите **Установить_ИИ.bat** после обычного запуска: пакеты и веса моделей могут занимать много места и загружаются при первом использовании. Сами видео не отправляются в облако.

Звуковые события проверяются по всему кандидату окнами до 10 секунд с перекрытием. Для объектов/сюжета видео читается порциями до 24 секунд с перекрытием: около 6 кадров в секунду для трекера объектов и около 1 кадра в секунду для оценки сюжета. X-CLIP получает последовательные группы из восьми кадров, включая конец отрезка; итоговая оценка учитывает наиболее выраженное событие. Короткие события между выбранными кадрами всё ещё могут быть пропущены. Качество нового метода нужно проверять на ваших поездках.

Если один дополнительный режим не сможет обработать ролик, остальные режимы продолжат работу. Замечание укажет режим и секунду сбоя. Подробный журнал `moto_analysis.log` сохраняется в папке вывода: если ошибка повторится, пришлите этот файл для диагностики. Журнал содержит имя файла и трассировку ошибки, но не кадры и не звук. Для проверки результата без облегчённой копии снимите галочку LRF и повторите анализ.

Телеметрия выключена по умолчанию, поскольку у вашей Action 5 Pro нет GPS-пульта. Если в исходном MP4 есть поддерживаемые теги, программа попробует прочитать их через отдельно установленный [ExifTool](https://exiftool.org/). Можно также положить одноимённый GPX рядом с MP4. При отсутствии данных обычный поиск продолжает работать.

Явные решения **ПРИНЯТЬ** и **ИСКЛЮЧИТЬ** сохраняют оценки сигналов, выбор и причину отказа в `moto_preferences.json` в папке вывода. При исключении можно указать скучное событие, качество, границы или повтор. Отказы из-за границ/повторов сохраняются, но не обучают модель считать сам сюжет неинтересным. После пяти положительных и пяти отрицательных примеров подходящего типа персональная оценка составляет 30% итогового балла следующего отбора. В признаки добавлены качество, длительность и характеристики движения/звука. После трёх явно принятых ручных правок программа учится типичному сдвигу начала и конца, ограничивая поправку четвертью исходной длины. Это простое обучение предпочтениям и границам, а не переобучение YOLO или X-CLIP. Старый JSON совместим; удаление его сбрасывает историю.

При пакетной обработке файлы шортсов от разных исходников размещаются в отдельных папках. Рядом создаётся JSON с оценками и параметрами экспорта. Повторный экспорт с тем же именем перезаписывает готовый шортс, исходный MP4 остаётся нетронутым.

## Проверка

После установки базовых зависимостей: `python -m unittest discover -s tests -v`. Тесты проверяют кэш и его сброс, восстановление очереди, проект, фильтры, поздние звуковые события, окна кадров, обучение границам и остановку реального экспорта. При отсутствии тестового MP4 тесты создают короткую запись через FFmpeg. Новые тесты также проверяют разделение исходников, совпадающие копии, отмену обучения, сохранность прежней модели, изменение MP4, кэш признаков и восстановление обычного отбора при сбое. GPU/нейросети в автоматических тестах частично подменяются: запуск реальных весов и драйверов нужно отдельно проверить на целевом компьютере.

Тесты v21 дополнительно сверяют реальные кадры дробных границ с независимым декодированием MP4 целиком, проверяют последний кадр файла, вертикальное видео, переменную частоту кадров, кэш, замену устаревших запросов и отмену при закрытии. Для новых кадровых тестов используются только базовые зависимости и FFmpeg.

Тесты v23 дополнительно проверяют обучение полностью без оригиналов, совместимость сохранённых признаков, восстановление проекта без повторной загрузки, замену MP4 с тем же именем, безопасность очистки загрузок, реальный загрузчик Google SDK с контролируемым ответом, отслеживание событий, границы реплик и семантические повторы. В сборке v23 было 59 автоматических проверок. Тогда отдельно на Linux проверены реальные faster-whisper Base, X-CLIP и BoT-SORT, а также окна Tk 8.6. В v23.1 проходят 72 проверки; новые сценарии покрывают полный цикл с настоящим MP4, последовательную очередь, остановку скачивания и очистки, ошибки записи, целостность признаков и сохранение настройки очистки. Тяжёлый визуальный кодировщик в интеграционных тестах v23.1 заменён фиксированными признаками. Авторизация и скачивание из реального Google-аккаунта и запуск на Windows требуют проверки на вашем компьютере. Эти проверки подтверждают работу функций, а не качество отбора ваших поездок.

Тесты v22 проверяют числовую сортировку длительности, таймкодов и баллов, порядок имён с числами, переключение направления и обновление списка. Отдельно проверяется, что после сортировки выбранная строка открывает свой исходник и свой готовый файл, а оценка пользователя записывается для правильного фрагмента.

## Обучение из терминала

```bash
python -m pip install -r requirements-learning.txt
python learning.py --folder learning_data --import training_examples/urban_annotations.json --download-references --train
python learning.py --folder learning_data --import annotations.json --videos recordings --train
```

Включение результата выполняется в окне обучения. Основная CLI-команда использует ту же папку `learning_data`; при необходимости задайте `--learning-folder path/to/learning_data`. Формат собственного JSON: `sources` — список объектов с `id`, `file`, `group`; `examples` — список с `id`, `source_id`, `start`, `end`, `accepted` (true/false), необязательными `label`, `category`. Таймкоды в секундах, путь `file` относительно JSON или абсолютный.
