# Рабочие обновления v23.1

Основа — архив `Moto_Shorts_NEON_v23_1.zip`, предоставленный пользователем.
Это доработка v23.1, а не восстановленная версия v23.2.

## Изменения

Добавлены настройки производительности для Windows/RTX 50:

- Необязательное получение признаков для обучения без оригиналов. Прежний режим
  включён по умолчанию; при выключении скрытое извлечение X-CLIP не запускается.
- Прямое использование готового совместимого вектора события при повторном анализе.
- Подробный статус подготовки признаков, версии CUDA/PyTorch в отчёте оборудования,
  `Check_NVIDIA.bat` и установщик CUDA-сборки `Install_NVIDIA_RTX50.bat`.
- Отчёт времени этапов `moto_performance.json` в папке вывода.

См. `PERFORMANCE_WINDOWS_RU.md`. Отдельные GPU-пакеты предназначены для Windows;
их установка и фактическая скорость на RTX 5050 Laptop здесь не проверялись.

Встроен предоставленный пользователем LUT DJI Osmo Action 5 Pro D-Log M → Rec.709 V1.
В окне экспорта выберите «D-Log M + LUT» — отдельное скачивание или выбор файла
не нужны. Кнопка «ВСТРОЕННЫЙ DJI» сбрасывает путь к своему LUT, «ДРУГОЙ LUT»
сохраняет возможность внешней таблицы. В CLI достаточно `--color dlog` без `--lut`.
Режим «Без коррекции» остаётся исходным выбором; профиль видео автоматически
не определяется. При переносе распаковывайте всю папку вместе с `assets`.

Встроенный файл совпадает с загруженным по SHA-256; таблица не менялась.
Путь определяется относительно программы, поэтому буква диска и рабочая папка
не влияют на выбор встроенного LUT. Для FFmpeg файл копируется во временную
папку с простым именем, как и внешний LUT в исходной реализации.

Предыдущие изменения также включены:

1. Модель предпочтений больше не использует отказы «Тряска / плохое качество»
   как отрицательные примеры интересности. Причины отказа теперь общие с визуальным
   классификатором: качество, границы и повторы сохраняются в истории, но не учат
   считать сюжет скучным. Уже сохранённые решения учитываются по этому правилу
   при следующем построении модели предпочтений; ручное исправление JSON не нужно.
   Это не добавляет отдельную обучаемую модель качества и не переобучает X-CLIP.
2. При сканировании один раз подготавливаются нормализованные сигналы и временной
   ряд базовой активности. Оценка следующих кандидатов использует их повторно.
   Формулы и шкалы оценок сохранены. В дисковый кэш и память событий новые
   производные массивы не записываются; формат проектов и признаков не менялся.

## Проверки

- До изменений: 72 успешных теста из архива.
- После изменений: 77 успешных тестов, без пропусков.
- После встраивания LUT: 83 успешных теста, без пропусков. Новые проверки
  включают настоящий экспорт со встроенной таблицей, изменение пикселей,
  внешний нейтральный LUT, папки с русскими буквами и пробелами, неизменность
  оригинала, целостность ресурса и сообщения о недостающих файлах.
- После изменений производительности: 94 успешных теста, без пропусков.
  Проверены отсутствие скрытого кодировщика при выключенной настройке,
  восстановление очереди, подготовка признаков при повторном включении,
  прямое использование памяти, пересчёт повреждённых признаков, сохранность
  временного MP4 Drive, отчёт времени и отказ диагностики при ошибке CUDA.
- Регрессионные тесты проверяют сохранность решений, отсутствие влияния отказов
  по качеству на модель интересности, прежние числовые оценки дробных интервалов,
  последний неполный интервал и отсутствие повторного расчёта при использовании кэша.
- Существующий набор включает реальное декодирование MP4, экспорт FFmpeg,
  сохранение SQLite и проекты. Тяжёлые модели и ответы Google в соответствующих
  интеграционных сценариях подменяются контролируемыми данными.
- Дополнительно выполнен запуск CLI на сгенерированном MP4: получен четырёхсекундный
  ролик 720×1280, H.264/AAC; проект и манифест записаны, SHA-256 оригинала не изменился.

На синтетических сигналах часовой записи расчёт оценок 40 интервалов занял
примерно 0,74 с до изменений и 0,024 с после, включая подготовку сигналов.
Оценки, признаки и сигнатуры всех 40 интервалов совпали точно.
Это локальный замер одного этапа, а не ускорение полного анализа видео.

## Ограничения и следующие шаги

Полные городские поездки пользователя не предоставлены. Качество отбора,
пропуски событий и время ручной проверки пока не измерены. Новые профили съёмки,
ручное добавление событий и автоматическое сопровождение кадра пока не добавлены.

В облачной среде проверяется базовая обработка без GPU. Настоящие X-CLIP,
YOLO/BoT-SORT, faster-whisper, авторизация Google и GUI Windows в этом обновлении
не проверялись. Для запуска на Windows используется прежний `Запустить.bat`.
